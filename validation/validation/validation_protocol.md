# Paper A · RQ1 验证协议：前视预警验证 (v0.1)

> 对应研究问题: "LLM 从新闻/政府公告/行业报告抽取的风险情报，能否在真实中断发生前给出可行动预警？"
> 本协议把 RQ1 转成可验证目标。核心指标: **命中率、平均 lead time、精度、召回**，与人工情报基准对比。

## 1. 核心定义

### 1.1 Ground Truth 事件集（GT）
一组**事后确认**的真实供应链中断事件，每条记录：
- `event_id`, `event_name`（如 red_sea_crisis_2023）
- `gt_onset_date`: 中断**实际开始**日期（事后认定，如红海商船遇袭导致苏伊士改道开始）
- `gt_onset_evidence`: 认定依据（来源 + 日期），保证 onset 可追溯
- `commodities / companies / geographies`: 受影响范围（用于信号匹配）
- `category`: 事件类型（与 schema 的 event_type 对齐）

候选 GT（2026-08 初定，文献检索后补证据）:
- 红海危机 (2023-11~2024) · 芯片出口管制 (2022-10~) · 苏伊士堵船 (2021-03) · 疫情 (2020-01~)
- 备选: 泰国洪水硬盘链 (2011) · 瑞萨地震 (2016) · 芯片荒 (2021)

### 1.2 信号库（LLM 抽取产物）
见 `shared/schema/event_schema.json`。每条信号有 `signal_date`（报道日期）与 `temporality`。

### 1.3 命中判定
信号 s **命中** GT 事件 e，当且仅当：
1. `s.signal_date < e.gt_onset_date`（严格早于 onset，保证是"预警"而非"报道已发生事实"）；
2. s 与 e 在商品、公司或地区上可匹配（匹配规则见 1.4）；
3. `s.temporality in {forward_looking, latent}`（confirmation 不算预警）。

### 1.4 匹配规则（先宽后严，两级）
- **宽松匹配**: 地区或商品任一匹配（地区匹配用区域包含，如 "Red Sea" ⊂ "Middle East"）。
- **严格匹配**: 商品匹配 + 地区匹配，或公司匹配（公司名/别名表）。
论文主体报告严格匹配，宽松匹配作为稳健性检验。

## 2. 指标

对每个 GT 事件 e，窗口 [e.gt_onset_date - T, e.gt_onset_date)（T 默认 180 天）内：

| 指标 | 定义 |
|---|---|
| 命中 (hit) | 存在至少一条命中信号 |
| 漏报 (miss) | 窗口内无命中信号 |
| lead time | onset_date − 最早命中信号的 signal_date（天数，仅对命中事件计算） |
| 命中率 | 命中事件数 / GT 事件总数 |
| 平均 lead time | 命中事件 lead time 的均值（中位数同时报告） |

**信号级指标**（预警的"噪声水平"，决定可行动性）:
- 精度 precision = 命中信号数 / 信号总数（窗口内 forward_looking+latent 信号）
- 召回 recall = 命中信号数 / 应有信号数（GT 事件的已知真实信号，来自人工复核）

**对比基准**（同一验证集上）:
1. 人工情报基准: 1-2 名领域研究员在盲评条件下从同一新闻流标注预警信号（只标"是否构成预警"与日期，不做全抽取）。人工 vs LLM 对比命中率与 lead time。
2. 传统 NLP 基准（可选）: 关键词规则 / 无监督事件检测（BERTopic + 时间聚簇），论证 LLM 增量。

## 2b. 可信度指标（RQ4）

### 2b.1 置信度校准（Confidence Calibration）
LLM 自报置信度 `confidence` 应与实际命中率一致。
- 分箱: 按置信度 0.1 分箱（B1=[0,0.1), ..., B10=[0.9,1.0]）。
- ECE = Σ_m (|B_m|/N) · |acc(B_m) − conf̄(B_m)|，其中 acc = 箱内信号命中 GT 的比例，conf̄ = 箱内平均自报置信度。
- 区分力检验: 高置信度 (c ≥ 0.8) vs 低置信度 (c < 0.5) 信号的命中率差异。
- 产出: 校准曲线图（置信度 vs 实际命中率）+ ECE 数值。
- 用途: (i) 预警阈值设定（只采信 c ≥ ĉ 的信号）; (ii) 反哺 Paper B 的最优依赖模型参数。

### 2b.2 Trigger 忠实性审计（Faithfulness）
每条信号的 trigger_phrases 必须逐字出现在原文中（防幻觉机制）。
- faithfulness = trigger 短语全部逐字命中的信号占比。
- 若某信号 trigger 未逐字命中，视为疑似幻觉，单独记录供审计。

## 3. 可行动性判据（RQ1 的"可行动"落点）

预警有效，当且仅当同时满足：
- 命中率 ≥ 0.7（10 个 GT 事件中至少 7 个被提前预警）；
- 平均 lead time ≥ 7 天（经理有足够时间启动 BCP/调整订单）；
- 精度 ≥ 0.3 且命中信号数 / 信号总数不过度稀释（低于该线说明噪声淹没信号）。
阈值初定为研究假设，文献检索后用领域标准校准，不作为投稿时拍脑袋的结论。

## 4. 数据源与时间窗口（待定项，需网络/数据获取后确认）

- 新闻源: Reuters / Bloomberg / 行业媒体（如 SCMR、FreightWaves）/ 政府公告（出口管制、FEMA）。
- 时间窗口: 覆盖候选 GT 事件前后各 180 天。
- 抽样: 按天采样避免偏差；负例（无关新闻）按比例混入，用于评估误报率。

## 5. 标注成本估算（风险日志）

- 每个 GT 事件需要人工复核信号匹配与 onset 认定：约 2-4 人日/事件 × 10 事件。
- 人工情报基准: 1-2 名标注员 × 新闻流全量预筛，成本最高，建议只对 2-3 个代表性事件做。
- 建议: 先用 1 个事件（红海危机）做 pilot，跑通全链路再扩。
